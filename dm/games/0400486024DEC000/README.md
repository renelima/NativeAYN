# The Legend of Zelda: Ocarina of Time (`0400486024DEC000`)

A Switch 2 game: update v131072 over base v65536, from a `.nup` dump (base and update packages, each with its own ExeFS and RomFS; [NUP support](../../../android/NUP.md)). SDK 22.2.8 built for the Switch 2 (spec Ounce), NVN2. Nintendo EPD's engine (sead / agl / gsys, Phive, Havok), modules `main` + `subsdk0` (NintendoSDK movie 22.2.8) + `sdk`. **In bring-up: boots on Android to the title screen and its opening movie** ([Boot](#boot-android-v131072); not tried on the Mac or iOS). The profile, the Android rewrite and the shader library are made on Linux (no Mac). Its closest relatives here are [Mario Kart World](../0400C3F00006E000/README.md) (virtual address memory, a movie module, the same engine) and [Donkey Kong Bananza](../040074A01BF12000/README.md).

## What it needs

| Setting | Where | Why |
|---|---|---|
| `modules main subsdk0 sdk` | [`game.tsv`](game.tsv) | `subsdk0` is NintendoSDK movie 22.2.8 (824 exports); `main` imports its movie player (`nn::movie`, 34 imports), which the host does not supply, so it is loaded (as Mario Kart World's) |
| `sys_resource 0x3000000` | `game.tsv` | the NPDM declares 48 MB of system resource: virtual address memory on (as Mario Kart World; unlike Donkey Kong Bananza) |
| `mem_reserve 0x300000000`, `mem_alias 0x100000000` | `game.tsv` | **not measured**: Mario Kart World's layout, taken over because this game too has virtual address memory and sets a heap. The Mac heap check that sizes them was not run. On the phone they held so far: a 6.20 GB heap, and about 1.5 GB of the 4 GB alias region used so far. The 4 GB alias region also holds the SDK's 1 GB AddressRegionManager node area, which the SDK-wide cut (`dm/tools/sdk_patches.py`) does not reach on this `sdk` ([Rewrite](#rewrite-of-v131072)) |
| `app_pool 0x240000000` | `game.tsv` | the Switch 2's 9 GB, as Donkey Kong Bananza (not measured) |
| `render_cond on` | `game.tsv` | taken over from Donkey Kong Bananza and Tears of the Kingdom (agl's render buffer binding); not checked on this game |
| `shader_groups … /Layout2Shader/=layout` | `game.tsv` | Tears of the Kingdom's groups plus `Layout2Shader/` (the UI's `MergeShader`) |

The phone needs a GPU driver with `VK_EXT_map_memory_placed` (placed pools; the app's readiness check): the POCO F8 Pro's system Qualcomm driver (0800.71, Vulkan 1.3.284) lacks it, so it runs on Turnip (Mr_Purple's PurpleVK 26.3.0, T30). About 10.0 of the phone's 10.9 GiB were in use while it played, and Android ended background apps.

The SDK-wide rules "AddressRegionManager node area 1 GB → 62 MB" and "regions of 4 MB and more aligned to 2 MB" match no function of this `sdk` (a new implementation, not reviewed); the 4 GB alias region is sized to hold the 1 GB node area instead.

A diagnostic cut, off by default ([patches.py](patches.py)): `DM_OOT_MAX_RES=1` in the rewriter's environment holds the game's dynamic-resolution update (`main+0x805aa0`) at scale 1.0 by making its branch to the "dynamic resolution off" path unconditional (`main+0x805bd0` `e8410036` → `0f020014`), to tell the dynamic-resolution floor (683x384) and the NDSR upscaler apart from the black gameplay. Rewrite with it into a pack folder of its own (`--out`): the rewrite key does not cover the environment. Not yet tried on the phone.

## Boot (Android; v131072)

Phone: Xiaomi 2510DPC44G (POCO F8 Pro), Snapdragon 8 Elite (Adreno 830), 12 GB, Android 16 (HyperOS), Turnip ([What it needs](#what-it-needs)). Everything was built on Linux from the `.nup`: `profile_guess.py`, `pack_android.py`, `shader_split.py` and `vk_android_build.py` (the translator `dm/gfx/tools/dmsh_xlate_bin/dmsh_xlate.dll` through a `dotnet` wrapper; its source matches `dmsh_chain.lock`); test APK `-PnxApp=oot -PnxPackEngine=fake`.

First shader library: 42,321 shaders, 42,228 built; 19 fail to translate (Ampere instructions the translator does not implement, and the mesh program without a mesh layout, [Files](#files)) and 74 fail `spirv-val` (vector access out of bounds). A rebuild with the NDVE shaders (step 8) was running when this was written.

Each stop below was met on the phone in this order and fixed in the host (general fixes unless said otherwise; uncommitted, 2026-11-07):

1. **`auddmg:u` abort** at boot: Result 0xa99 at `sdk+0x1f61ac`, from SDK 22's `ListVirtualInputDevices` in the game's microphone manager (constructor `main+0xed1440`, open `main+0xf4860c`, list `main+0xf48128`), whether or not the voice ocarina is on. Fixed by a hook with no device; the game skips the open (`main+0xf4812c`). Checked on the phone. [Virtual input devices listed through `auddmg:u` (SDK 22)](../../../docs/reference/audio.md#virtual-input-devices-listed-through-auddmgu-sdk-22).
2. **gRPC abort** at boot: NPLN 1.55.1's `grpc_event_engine_init` aborts (`main+0x21f0c7c`) when its wakeup-fd check (`main+0x21f3bd0`) finds no eventfd. Fixed by local eventfds in `hle_net.c`. Checked: `socket: eventfd 512 made`, the engine starts. The flag values (Semaphore 1, NonBlock 4) are not checked. [Local eventfds for gRPC with the network down](../../../docs/reference/services.md#local-eventfds-for-grpc-with-the-network-down).
3. **SIGILL in a fiber switch**: `nn.npln.GrpcDispatcher` at `sdk+0x16d40c` (`autiasp` in `DispatchFiberContext`), the fiber's entry signed on another thread by `FiberImplByHorizon::Initialize` (`sdk+0x16d0d0`) with that thread's IA key. Fixed by turning the IA key off on guest threads. Checked with `DM_PAC_PROBE=1`: IA differed on all 85 threads before, unsigned on all 86 after, no crash. [Pointer authentication keys differ between Android threads (`nn::os` fibers)](../../../docs/reference/threads.md#pointer-authentication-keys-differ-between-android-threads-nnos-fibers).
4. **AV1 movies**: the movie library aborted (Result 0xfa86f, `subsdk0+0xf9bc`) when `InitializeAv1DecoderByTransferMemory` failed. Fixed by AV1 on `AMediaCodec` (`mavc_new_av1` in `dm/host/plat/movie_avc_android.c`, the AV1 family in `hle_codec_video.c`; the Mac and iOS still fail it). Checked: `c2.qti.av1.decoder` decodes 1920×1080, first picture, sound plays. [`nn::codec` video decoders taken over](../../../docs/reference/movies.md#nncodec-video-decoders-taken-over), [SDK 21's `nn::codec` entry points](../../../docs/reference/movies.md#sdk-21s-nncodec-entry-points).
5. **Controller applet every frame**: the game asks for exactly one player (`ShowControllerSupport` with 1 to 1); HyperOS's virtual device `uinput-xiaomi` was player 1 and the Bluetooth PlayStation pad player 2, and the host capped only the returned count, so the game's check (`main+0x3b262c0`, 3 for a controller past the wanted count) failed and it asked again. Fixed in `hle_hid.c` (`g_applet_cap`): players past the maximum are disconnected and feed player 1. Checked: the applet opens once, the pad's input reaches the game; `t_hid` 150 of 150 on the phone. The front end also stops giving a player at connect to a device with no stick and no A / B button (`GameActivity.java` `controller`), which leaves `uinput-xiaomi` out; not checked on the phone on its own. [The controller applet disconnects players past its maximum](../../../docs/reference/services.md#the-controller-applet-disconnects-players-past-its-maximum).

Fixed in `GameActivity.java` `immersive()`: both system bars hidden, shown for a moment by a swipe, the cutout's short edges used, again on resume and focus. Checked by the user.
